Suggested Project Path

  • I start with quality-gate-report.md to confirm the generated artifacts match the current source.
  • I open promotion-decision-review.html to inspect evidence, claims, split gates, audit findings, and trace.
  • I use eval-coverage-report.md to verify coverage across benchmark corpora and guardrails.
  • I use reference-catalog-report.md to inspect which GitHub projects and external sources informed the design.
  • I use service-interface-report.md, service-runtime-demo.md, service-api-readiness.md, and service-mcp-readiness.md to inspect the service boundary.
  • I open review-workbench.html to inspect approval actions, evidence coverage, claim grounding, audit, evals, and trace.
  • I use portfolio-demo.json to inspect promotion, abstention, benchmark, baseline comparison, and failure recovery paths.
